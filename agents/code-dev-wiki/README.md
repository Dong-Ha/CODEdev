# Code Dev Wiki

feature-dev의 7단계에 로컬 LLM Wiki 탐색과 코드 대조를 통합한 **단일 에이전트 지침**입니다.

- [code-dev-wiki.md](code-dev-wiki.md): 실행 지침과 단계별 완료 조건.
- 입력 계약: [CODEdev 요청 계약](../../docs/orchestration.md)의 task.payload.
- 위키 입력: 현재 필드인 environment.wiki_link 사용 (선택).
- 기존 [code-dev.md](../code-dev.md)는 레거시 실험 모드용으로 유지합니다.

## 현재 연결 상태

이 폴더 추가만으로 웹의 “Claude Code로 바로 전달” 동작은 바뀌지 않습니다. 현재 cli_dispatch.py는 요청을 텍스트로 전달하고, 기본 실행기는 파일 접근 도구를 제한합니다. 이 지침의 자동 로딩, 위키 읽기, 코드 수정, 단계별 상태 저장은 웹 실행기에 아직 연결되지 않았습니다.

## 수동 사용

로컬 파일 접근을 허용한 Claude Code 대화 세션에서 이 파일을 명시적으로 읽도록 요청하고, CODEdev에서 내보낸 요청 JSON을 함께 전달합니다. 아래 경로는 실제 로컬 경로로 바꾸세요.

```text
/path/to/CODEdev/agents/code-dev-wiki/code-dev-wiki.md를 읽고 그 절차로 진행해.
요청은 /path/to/request.json의 task.payload(또는 payload 객체)를 사용해.
이번 실행은 분석과 변경안 제안까지 허용한다.
소스 읽기 경계는 요청의 scope.read_boundary다.
위키가 경계 밖이면 읽기 전에 필요한 경로를 알려줘.
파일 수정과 빌드·테스트 실행은 아직 허용하지 않는다.
```

현재 payload의 revision/파일 상태를 확인할 수 없는 세션은 미검증 사실을 남기고 적용을 보류합니다. 수정 단계로 진행할 때는 승인할 변경안, 현재 scope와 revision 재검증 결과, 별도 허용된 검증 명령을 전달하세요. 기존 작업 승인이 이미 이를 충족하면 중복 승인은 필요하지 않습니다.

agents/는 CODEdev의 일반 파일 폴더이며 Claude Code 자동 등록 경로가 아닙니다. 위 예시는 파일을 직접 읽게 하는 방법이고, /feature-dev 명령이나 별도 서브에이전트 설치를 요구하지 않습니다.

## 흐름

요구사항 파악 → 위키·코드 탐색 → 불명확한 사항 해소 → 구현 설계 → 구현/변경안 → 리뷰·검증 → 결과 보고.

위키는 2단계에서 근거 표로 정리하고 4·6단계에서 다시 대조합니다. 위키 미지정은 코드 탐색으로 진행하고, 지정한 위키 접근 실패는 결과에 남깁니다. 문서와 코드 충돌이 구현 판단에 영향을 주면 질문으로 반환합니다.

## 웹 실행기에 연결할 때

1. 이 파일을 신뢰된 실행 지침으로 로딩하고 task.payload는 별도 작업 데이터로 전달합니다.
2. 현재 revision, 실제 경로, 허용 파일 목록과 사용자 변경을 재검증합니다.
3. 프로젝트와 별도 위키 읽기 경계, 수정 allowlist, 명령 실행 권한을 실행기에서 강제합니다. 프롬프트만으로 파일 접근을 제한할 수 없습니다.
4. 중복 실행 방지, 실행 인수/결과/취소, 질문 후 재개와 단계별 상태 저장을 구현합니다.
5. 현재의 텍스트 전송 전용 모드와 새 에이전트 실행 모드를 구분해서 표시합니다.

## 확인 시나리오

| 입력/상황 | 기대 결과 |
| --- | --- |
| 위키 미지정 | not_configured, 코드 탐색 진행 |
| 위키 경로 없음/읽기 거절 | missing/denied 및 영향 보고 |
| 프로젝트 밖 위키 | 별도 읽기 권한 확인, 없으면 접근하지 않음 |
| 위키와 코드 충돌 | 근거를 양쪽에서 제시, 중요 충돌은 blocked |
| 수정 목록 밖 변경 필요 | 범위 확대 요청, 파일 수정 안 함 |
| 스냅샷과 현재 환경 불일치 | 적용 보류, 재접수/재검증 요청 |
| 빌드 명령만 있고 실행 허가 없음 | not_run, 실행하지 않음 |
| 파일 도구 없는 기본 dispatch | 접근·수정 성공 주장 안 함 |
| 제안 전용 실행 | proposed, 실제 수정과 구분 |
| 검증 실패 | 실패/남은 문제 보고, 성공으로 표시 안 함 |
